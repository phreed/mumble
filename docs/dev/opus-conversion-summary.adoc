= Mumble SpeexDSP to Opus Audio Processing Conversion Summary
:toc:
:numbered:

== Overview

This document summarizes the comprehensive conversion of Mumble's audio processing pipeline from SpeexDSP to a modern Opus-based system.
The conversion maintains backward compatibility while providing superior audio quality and performance.

== What Was Converted

=== Audio Processing Components

==== Resampling
- **Before:** `speex_resampler_*` functions
- **After:** `OpusResampler` class using libsoxr
- **Benefits:** Higher quality resampling, better frequency response, reduced artifacts

==== Echo Cancellation
- **Before:** `speex_echo_*` functions
- **After:** `OpusEchoCanceller` class using WebRTC AEC
- **Benefits:** Advanced echo cancellation algorithms, better adaptation, lower latency

==== Audio Preprocessing
- **Before:** `speex_preprocess_*` functions
- **After:** `OpusAudioPreprocessor` class combining WebRTC APM + RNNoise
- **Benefits:** Superior noise suppression, improved VAD, better speech preservation

==== Compatibility Layer

The `AudioProcessingAdapter` provides a unified interface that works with both:
- Legacy SpeexDSP implementation
- New Opus-based processing

This enables:
- Gradual migration without breaking existing code
- Runtime switching between backends
- Easy testing and comparison

== Migration Path

=== Automatic Migration

When users first run Mumble with Opus processing:

1. **Settings Detection**
   - Existing audio preferences are detected
   - Quality settings are automatically converted
   - Echo cancellation preferences are preserved

2. **Graceful Fallback**
   - If new dependencies are missing, falls back to SpeexDSP
   - User is notified of fallback and missing features
   - No loss of functionality

3. **Progressive Enhancement**
   - Features are enabled as dependencies become available
   - Users can opt-in to advanced features
   - Settings are preserved across updates

=== Manual Migration

Advanced users can configure specific components:

1. **Resampling Quality**
   - Choose between speed and quality
   - Configure for specific use cases
   - Monitor CPU usage impact

2. **Echo Cancellation**
   - Select WebRTC AEC modes
   - Adjust aggressiveness levels
   - Configure for room acoustics

3. **Noise Suppression**
   - Choose between WebRTC and RNNoise
   - Combine multiple algorithms
   - Fine-tune suppression levels
